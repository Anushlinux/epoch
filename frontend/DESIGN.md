# Task workspace design

Mode: **Operate**. The first screen supports inspecting an interrupted release task, its sourced checkpoints and its next unresolved action. It is a workspace, not a landing page.

The visual direction is a quiet work ledger: a persistent muted navigation rail, a clear task identity, compact section tabs, a primary checkpoint column and a narrower original-intent column. White evidence surfaces sit on a pale green-neutral canvas. Forest green identifies navigation/actions; amber signals attention; red marks failed or rejected fixture records. State always has text, never color alone.

System sans type is appropriate for repeated task work. Fixed type sizes, short text measures and generous separation between groups prioritize scanning. Code uses monospace only in inspectable JSON/diffs. At narrow widths the navigation collapses to brand/new-request, context stacks below checkpoints, and forms remain readable without horizontal document scrolling.

Every screen retains fixture provenance. Outcome labels use a dot and text, with no celebratory or optimistic checkmark. Repair activation and task completion are separate. Native buttons, details, inputs and dialog behavior provide keyboard semantics. Tabs support arrow/Home/End keys. Motion is limited to short control-state transitions and respects reduced motion.

No incumbent visual system or assets existed. The user's Operate workspace brief and authorization to proceed with minimal provisional tooling govern this implementation. No broader brand, stack, backend contract or deployment decision is implied.
